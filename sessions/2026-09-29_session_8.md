# Session 8: the kit's own commits ignored the manifest

**Date**: 2026-09-29
**Branch**: `feature/session-8-commit-trailers` (worktree `.claude/worktrees/session-8-commit-trailers`)
**Type**: fix

## Context

Only two commands in lifecycle-kit create a commit, and neither read
`commit_convention` or `commit_trailers`. Under `forge: none` the finalize merge
was `git merge --no-ff "$BRANCH" -m "Merge $BRANCH"`, with no trailer. In Puri
session 3 the `commit-msg` hook refused it, and the merge was left staged in the
primary checkout. The session-end log commit hardcoded
`docs(sessions): add session <N> log ...` and stated that `commit_trailers` was
`none`. Those were one project's values, written into the skill as if they were
facts about every project. Lifecycle-kit 0.3.3 makes both commits build their
messages from the manifest.

## What happened

1. **The format is defined once, in the template.** `lifecycle-manifest.template.md`
   gains a *Commit messages* section. `commit_trailers` is `none`, or one or more
   `Key: value` lines joined by ` + `, which is the form this repo's own manifest
   already used. `<url>` resolves from the session's commit attribution and
   `<model>` from the running model. Any other angle-bracket text, such as an
   email address, is literal. If a placeholder cannot be resolved, the skill
   stops and asks, and it never commits without the trailer.
   `commit_convention` is the subject pattern. A convention with no prefix gets
   a subject with no prefix. The worked examples in the section are a list
   rather than a fenced YAML block, because a copied template must keep a
   single YAML block, and a second block starting `commit_trailers:` at column
   0 would be the first one a grep finds.
2. **All trailers go in one `-m`, not one `-m` each.** This departs from the
   spec as written, for a reason tested here. git reads only the last paragraph
   of a message as trailers, and each `-m` is its own paragraph. So
   `-m "Co-Authored-By: ..." -m "Claude-Session: ..."` leaves `Co-Authored-By`
   as body text. `git interpret-trailers --parse` confirmed it, and in the
   scenario's `split` replay a hook that parses trailers refused the
   one-`-m`-per-trailer form outright. With a single trailer the two forms are
   the same.
3. **`none.md`'s merge takes the trailers**, and phase 3 gains two steps.
   - Step 0, re-entry. If the branch is already merged, go to phase 4. If the
     primary is mid-merge, report it and stop.
   - Step 5, recovery from a refused merge. This case is identified by
     `MERGE_HEAD` set and no conflicted paths. The skill reports the hook's
     output, says the checkout is mid-merge, and gives the completing command,
     `git commit -m "Merge <branch>" -m "<trailers>"`. It runs that command
     only on the user's go-ahead. If the hook refused the manifest's own
     trailers, the skill says the manifest and the hook disagree. The rules
     against `--no-verify` and against auto-aborting still hold.
4. **session-end's log commit follows the manifest.** The subject fills the
   convention with `docs`, `sessions` and `add|update session <N> log for ...`.
   `docs(sessions): ...` survives only as the labelled example for a prefixed
   convention. The sample output no longer repeats the prefix.
5. **`validate-manifest.sh` checks the shape of `commit_trailers`** at session
   start. A quoted value is taken whole, so `Refs: #12` survives. An unquoted
   value loses its trailing comment. The value is split with POSIX awk, not
   GNU `sed \n`, so the check also works on macOS. Nine values were tested,
   covering valid ones, a missing colon, an empty piece and a keyless piece.
6. **A benchmark scenario, `trailer-hook`**, in three modes. The hook reads the
   *parsed* trailer block, so a split trailer fails it.
   - `hook` sets a no-prefix convention and a hook that refuses without the
     trailers.
   - `legacy` sets `none` and a prefixed convention, and requires output
     byte-identical to before.
   - `refuse` uses a hook that also demands a trailer the manifest lacks, on
     merges only.

   An aborted merge is told apart from one never started by `ORIG_HEAD`, which
   is per-worktree and which setup never sets in the primary.
7. **Version 0.3.3.** The installed plugin needs `/plugin update` and a Claude
   Code restart before any project sees this.

## Test results

The assertion was checked first by deterministic replays, with no agent. The
correct commands pass all three modes. These fail:

- the old messages under `hook`
- one `-m` per trailer under `hook`
- trailers under `legacy`
- `--no-verify` under `refuse`
- `merge --abort` under `refuse`

A `refuse` run that never merges comes out VOID.

After that, one fresh Opus 5.5 agent ran each mode against the edited skills.
All three passed on ground-truth git state.

- **hook.** The subject was `add session 501 log for trailers` and the merge
  was `Merge feature/session-501-trailers`. Both passed the hook with
  `Bench-Run: lck-trailer` and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  in one parsed trailer block.
- **legacy.** The output was `docs(sessions): add session 501 log for trailers`
  and a bare `Merge feature/session-501-trailers`, exactly as before.
- **refuse.** The merge was left mid-merge, with `main` unmoved and the branch
  kept. The report named the missing `Ticket: BENCH-1` as a disagreement
  between the manifest and the hook, and gave the completing command with that
  trailer added.

No agent added a trailer the manifest did not name. That includes the
`Claude-Session:` line from its own attribution instructions.

## Decisions worth remembering

- A merge subject stays `Merge <branch>` under any convention. The spec asked
  for that, and it is git's own form.
- The recovery step reports and hands over. It does not complete the merge by
  itself. After this fix, a refusal means the manifest and the hook disagree,
  and only the user can say which of the two is wrong.
- The Puri case only needed a trailer, but the scenario's hook parses trailers,
  not grep, because a grep would have passed the split form this session found
  to be wrong.

- The shellcheck gate fails on any Windows checkout with `core.autocrlf=true`.

  content would fix it. Both are outside this session's scope.
- Out of scope, noted: merges made by the forge on GitHub or Forgejo carry the
  forge's own message, and no local hook sees them. knowledge-kit's hook
  templates were not looked at.
