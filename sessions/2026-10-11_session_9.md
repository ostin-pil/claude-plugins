# Session 9: the path claim as a manifest key

**Date**: 2026-10-11
**Branch**: `feature/session-9-claim-command` (worktree `.claude/worktrees/session-9-claim-command`)
**Type**: feat
**Session**: https://claude.ai/code/session_011pkzgEryMEoPZNfnpaHLjj

## Context

Worktrees keep parallel sessions off one HEAD, not out of one file. Puri
(D-054, its sessions 31 and 32) has every session claim the paths it will edit,
right after `/session-start` creates its worktree. A `pre-commit` hook then
refuses a commit outside the claim or inside another live session's. Until now
that step was Puri's own, written in its rules and run by hand. Sessions 31 and
32 left an ask for the kit to take it as an optional manifest key. This session
was run from Puri's session 67, which took that ask.

## What happened

1. **`claim_command`, optional, default `none`.** The template gains a *Path
   claims* section and the key under branches and worktrees. The key holds a
   shell command, run verbatim with no placeholders: it runs inside the new
   checkout, so it can read the branch from git. The design the section
   describes (a file per branch in the common git dir, live until the branch
   merges, enforced by `pre-commit`) is Puri's. Puri is not named, because
   nobody outside this machine can read it.
2. **`session-start` step 7 runs it.** It runs once, from inside the new
   worktree (or the switched checkout), after the create has succeeded and `N`
   is final. It is skipped for "stay on the current branch". The constraints
   name it as the one project command the skill runs.
3. **A refused path claim is not a collision.** This is the part worth the
   words. The skill already calls minting the number "the claim", and a
   refused number is retried at `N+1`. A path claim refused because another
   live session holds a file would only fail again under a new number, and
   would leave a second session where the user asked for one. So on a non-zero
   exit the skill shows the output verbatim and stops. There is no retry, no
   change of arguments, no new `N`, and the branch and worktree stay. What to
   do next is the user's call. The text says "path claim" everywhere the two
   could be confused.
4. **No validator change.** A bad `claim_command` fails at the one step that
   runs it, reports, and leaves nothing half-done. That is unlike a bad
   `commit_trailers`, which strands a merge.
5. **A three-mode scenario, `claim-command`.** A file remote, a log for session
   6 and a live `feature/session-7-other` with no log, so a correct run mints
   8. The claim script logs each call's branch and toplevel in the common git
   dir, where the assertion reads it from outside the agent.
   - `claim`: it runs once, inside the new worktree, and the claim lands.
   - `refuse`: the script refuses because session 7 holds `src/`. One call, no
     second branch, the worktree kept, the other claim untouched.
   - `none`: nothing runs.
6. **Version 0.3.4.** A project sees it after `/plugin update` and a Claude
   Code restart.

## Test results

The assertion was checked first by deterministic replays on 2026-10-11, with no
agent. The correct commands pass all three modes. Six wrong ones fail:

- under `claim`, never claiming;
- under `claim`, claiming from the primary checkout;
- under `refuse`, retrying at session 9;
- under `refuse`, removing the worktree;
- under `refuse`, claiming twice;
- under `none`, claiming anyway.

A run that creates no branch is VOID. The first replay caught a setup bug: the
scenario's `.claude/worktrees/` was untracked in the primary checkout, because
setup had not done what `worktree_ignore` says. It now writes the exclude.

Then one fresh Opus 5.5 agent per mode ran the edited skill. All three PASS on
ground-truth git state.

- **`claim`**: minted 8 past the live session 7, ran the script once from the
  worktree, and reported `feature/session-8-bench claims: src/`.
- **`refuse`**: one call; it showed both lines of the refusal verbatim, said
  the choice was the user's from the options they named, and kept the
  worktree.
- **`none`**: it saw `tools/claim.sh` in the repo and did not run it, "because
  the manifest does not name it".
