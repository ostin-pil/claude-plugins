# Session 5: the harness can watch, it just cannot ask

**Date**: 2026-08-07
**Branch**: `feature/session-5-trace-assert` (branch-only, primary checkout)
**Type**: feat

## Context

Session 4 closed the `stale-read` scenario as non-discriminating and left the
harness question open: can an outcome-asserting harness test a process
guarantee? Its analysis was right about the problem and wrong about the
constraint. The way out was already sitting in the scenario's own machinery.

## What happened

### 1. The constraint was read too broadly

Session 4's reasoning ran: the behaviour under test is a process guarantee, end
state is an outcome, and the harness distrusts agent self-reports, so the one
signal that would separate the arms is ruled out.

The first two hold. The third conflates two different things. "The agent's
self-report is never trusted" rules out asking the agent what it did. The shim
already writes its own log of every `git` call, from outside the agent, and the
agent neither produces that log nor knows its contents. It is not testimony, it
is surveillance, and asserting on it leaves the distrust rule intact.

The evidence was in the two run directories the whole time. Both were still in
`TMPDIR`, so nothing had to be re-run:

| Arm | First session-branch read | Fetches before it |
| --- | --- | --- |
| pre-fix 0.2.0 | line 10 | 1 |
| post-fix 0.2.2 | line 17 | 2 |

That is the fix's prescription, visible mechanically. The post-fix skill
re-fetches at the top of branch birth, before `N` is computed, so its branch
read is preceded by two fetches. The pre-fix skill's is preceded by one, and it
had to redo the work afterwards.

### 2. What was built

`assert-trace.sh` takes a shim log and asserts at least two fetches precede the
first session-branch read. Split into its own script rather than inlined into
`assert.sh` for one reason: it can then be tested against recorded traces, which
is exactly the thing the scenario could not do before.

Both traces ship as `fixtures/`. `selftest.sh` asserts the pre-fix trace is
rejected, the post-fix trace accepted, and a missing trace reported unusable
rather than passed. That last case matters as much as the other two: an
assertion that silently passes when its input is absent is worse than no
assertion.

`assert.sh` calls it and folds the result into its verdict. Baseline is now
pre-fix `FAIL` exit 1, post-fix `PASS` exit 0, verified by re-running `assert.sh`
against both original run directories rather than against the fixtures.

### 3. A bug the selftest would never have caught

`assert.sh` computed its own directory with `dirname "$0"` after it had already
`cd`'d into the test repo, so the path resolved against the repo and
`assert-trace.sh` was not found. Both arms then reported `FAIL` for the wrong
reason.

The selftest calls `assert-trace.sh` directly, so it was green throughout. Only
running the real `assert.sh` end to end surfaced it. Worth remembering when a
helper gets split out of a script: the split creates a new failure mode at the
seam, and the unit test for the helper cannot see it.

Fixed by resolving the directory before the `cd`, and a missing
`assert-trace.sh` is now an explicit error rather than falling through to a
generic failure. Uses the `unset CDPATH` form `ab1cee7` established over
`CDPATH=`, which shellcheck flags as SC1007.

### 4. What this still cannot do

An unfixed skill whose agent happens to fetch twice before the pre-flight passes
the check. The assertion is a proxy for intent, not proof of it. It is strictly
more than the outcome checks could see, and it fails the recorded pre-fix trace,
which is the property worth having. Both scripts say so in their headers rather
than leaving a future reader to assume more.

## Decisions worth remembering

- **Watching is not asking.** A mock on `PATH` writes a log the agent does not
  author and cannot see. That is process evidence that survives a rule against
  trusting self-reports, and it generalises to any scenario whose skill
  contributes a guarantee rather than a distinct end state.
- **Split the assertion out so it can be tested.** The reason `stale-read` had
  no baseline for a day was that checking it cost two agent runs. A helper plus
  recorded fixtures makes the assertion itself cheap to verify forever.
- **A missing input must not read as a pass.** Both the void-run guard and the
  unusable-trace exit exist for the same reason: the failure mode of this
  scenario is silently testing nothing.
- **Splitting a script creates a seam its unit test cannot see.** The `$0`
  resolution bug was invisible to the selftest and obvious on the first real
  run.
